lumen 0.5 showed what your commands cost. This release is about lumen itself: how fast a window is there, and how it stays current.

## Opening lumen again

- **A tab, not a second lumen.** Starting `lumen` while one runs, from the application menu, a launcher or another terminal, opens a new tab in the window you used last and brings that window to the front. The command in the tab runs about 9 ms after the launch. `lumen --new-window` asks for a window instead, `lumen --new-process` for a lumen of its own, and `launch` in the config sets what a launch opens by default.
- **The daemon.** `lumen --daemon` is a lumen without a window that does the GPU, font and config work at login, so the first window of a session shows its first frame after about 45 ms instead of 220. The install script turns it on as a systemd user service; the packages install it and leave it off.
- **Faster from nothing too.** A lumen that starts on its own starts the GPU while it loads its config and fonts, and tries Vulkan before anything else: its first frame comes about 120 ms sooner than in 0.5.

See [Opening lumen again](/docs/launching/).

## Updates

- **`lumen update`** brings lumen and the tools made for it (glint, crux, recap, seek, pulse and splice) to their newest releases, and with them the tools' agent skills, wherever an agent keeps them. `lumen update --check` only says what is out. A skill you changed by hand stays as it is.
- **Once a day by itself.** The install script turns on a timer that runs the update in the background, at the lowest priority, and tells you in a notification what changed. The packages install the timer and leave it off; turned on, it keeps the tools current and tells you once when a new lumen package is out, but never replaces the package.
- **New tools on their own.** Which tools there are comes from a list in lumen's repository, so a tool made later is kept current without a new lumen.

This is the first release with updates: installed with the install script or from source, it is the last one you install by hand. See [Updates](/docs/install/#updates).

## Typing

- **As smooth in power-saver as in balanced.** In the power-saver profile, every window was held to 30 frames a second: a key waited 22 ms for its frame, and the cursor's glide got two frames. lumen draws only when something changes, so it keeps the display's rate whatever the profile now: 4.7 ms from a key to its frame.

## For contributors

- **A lag recorder.** A build with `--features lag` records keys, the bytes to the program and back, and each frame on one clock; `scripts/lag.sh` types a fixed scenario in a hidden compositor and reports where the time from a key to its frame goes. See [Contributing](/docs/contributing/).

The Android app is the one from 0.3.0 with a new version number.

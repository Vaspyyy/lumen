lumen 0.6 opened at once and kept itself current. This release is about making it yours: the settings are in a menu, there are many more of them, and every key can be changed.

## The settings menu

- **`lumen settings`**, or **`/settings`** typed at a prompt, opens the settings in a menu. The arrows move and change, `Enter` flips a switch or lets you type (a font's name, a folder, a number), `r` puts a setting back to its default, `q` leaves. Each change is saved at once, and the window behind the menu shows it as you go.
- **Your file stays yours.** The menu changes only the line of the setting: your comments, the order, and the settings it doesn't show stay as they are. A change lumen wouldn't take is refused, with the reason.
- **`/settings` is lumen's only as those exact words at a prompt.** The shell never sees them, and a path like `/usr/bin/htop` still goes to the shell. It needs a shell that marks its prompts: fish 4 does, bash and zsh with [lumen's line](/docs/commands/#setting-up-your-shell).

See [Configuration](/docs/configuration/#the-settings-menu).

## More settings

- **Where new tabs start**: `new_tab_folder` is the folder of the tab you are in, as before, or your home folder, or any folder.
- **The window's frame**: `decorations = "desktop"` gives your desktop's own title bar, and `"none"` no frame at all: no round corners, no shadow, and none of the margin lumen kept around the window for it. On a tiling desktop that leaves a gap around lumen, `"none"` takes it away. `startup_mode` opens new windows maximized or on the whole screen.
- **The tab bar**: `bar = "auto"` shows it only from two tabs on, `"never"` not at all.
- **The cursor**: square corners (`rounded = false`), how long it blinks, how thick a beam or an underline is, and how it looks in a pane you aren't typing in.
- **Padding** across and down apart, `padding = { x = 4, y = 0 }`, as Alacritty writes it, and `dynamic_padding` to put the text in the middle of what is left over.
- **The font**: ligatures off, and how heavy plain and bold text are.
- **The mouse and the selection**: how far the wheel scrolls, whether the pointer hides while you type, and where a double click stops.
- **The clipboard**: whether programs may copy to it, paste from it, both, or neither. Copy only, as before, unless you say otherwise.
- **`[env]`**: variables every new tab gets, `TERM` among them.
- **A theme's 256 colors**: `indexed_colors` in an Alacritty theme is used now, not just accepted.

Most of these are in the menu too. Without a config file nothing changes: every default is what lumen did before. See [Configuration](/docs/configuration/).

## Your own keys

The `[keys]` table gives any key to one of lumen's actions, to text for the program, or back to the program:

```toml
[keys]
"alt-t" = "new_tab"
"ctrl-shift-t" = "none"                # goes to the program now
"shift-enter" = { send = "\u001b\r" }  # text, as if typed
```

A key named there no longer does what lumen gave it, and the others stay. A key or an action lumen doesn't know is a mistake, and lumen says which. There are new actions to bind as well: scrolling by a line, and opening pulse for when the tab bar, and the light in it, is hidden. See [Changing the keys](/docs/keys/#changing-the-keys).

## For programs

- **Which terminal this is**: lumen answers XTVERSION (`lumen 0.7.0`), and the size of a cell in pixels (`CSI 16 t`). Tools that draw pictures ask both, over SSH too, where the environment doesn't say which terminal they are in.
- **Answers in the order they were asked.** A program that asks several things at once now gets the answers in that order, also inside a synchronized update; an image's answer could come before the answer to a question asked ahead of it.

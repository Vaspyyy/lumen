This release closes the gaps the last two left open.

## Fixed

- **A background that a program sets is painted.** Scripts that switch a terminal to another theme, such as base16-shell, set the text, the background and the sixteen colors anew. lumen took the new text color and went on painting the theme's background, so a light theme came out as dark text on a dark pane. The pane now takes them all: the background fills the whole pane, and the selection and the faint mark of a command that went well take the color of the new text. So does the cursor: it takes the color a program sets for it, and the color of the text where the theme's cursor would be lost on the new background. Other panes and tabs keep the theme. See [Colors](/docs/colors/#colors-a-program-sets).

  ![Two panes side by side in lumen, with the same lines in both. The left one has the theme's dark background. In the right one a script has set a light background and dark text](/shots/light-pane.png)

- **A prompt that is written again stays one command.** A shell writes its prompt again under a list of completions, after `Ctrl+L`, and when the window changes its width. lumen took some of these copies for a new prompt, and after the window was made narrower, zsh with a prompt on the right could leave the marks of commands off by a line. bash and zsh now tell lumen when a prompt is a new one, so any other is the open one again, wherever it is written. fish doesn't say: its prompt on a cleared screen is now known for the same one, and for the rest lumen goes by where the prompt stands, as before. What is left of an earlier copy is not a command of its own, and it is not copied with what the command before it printed.
- **Prompts beside a command are not read as the command.** zsh's prompt at the right of the line, and the `> ` that bash and zsh put before a further line of a command, were taken for typed text where lumen reads a command from the screen. A shell on this machine marks them as prompts now, so a command of several lines is named as you typed it.
- **pulse is found when it is installed later.** lumen looked for [pulse](https://github.com/Vaspyyy/pulse) once, when it started. It now looks again every half minute until it finds it, so the light and the numbers on tabs show up in the lumen that is open.

bash and zsh get the new marks with the next tab you open: they come from the line `lumen shell-integration` that is in your startup file already.

## For programs

- `OSC 133 ; P` is read: `P;k=r`, `P;k=c` and `P;k=s` begin a prompt beside what is typed, which the next `B` ends. See [For programs](/docs/for-programs/#marks-for-commands).

The Android app is the one from 0.3.0 with a new version number.

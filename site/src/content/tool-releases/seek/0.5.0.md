## Fixed

- **`#N` counts the same in every tool.** A line that looks like a definition but sits inside a docstring or a template string was dropped by seek and counted by the other tools. In a `tool.py` whose module docstring holds `def run():`, seek's `run#1` was everyone else's `run#2`, so a `[changed]` mark could land on the wrong function. seek now takes its definitions from [Prism](https://github.com/Vaspyyy/prism)'s outline, as glint, recap and crux do, and `tool.py:run#1` means the same function everywhere.
- **Better labels for text that spans lines.** The `(string)` and `(comment)` labels come from Prism too now. Code inside a `${…}` that spans lines is code, Rust strings and shell heredocs or quotes that span lines are strings, and a Go raw string that ends in `\` no longer hides the function after it.
- **No hang on long lines.** seek labeled each hit by reading its line again from the start, so a minified line with hundreds of hits never finished. In a project with a 3.2 MB line in one file, `seek render` ran for minutes; now it takes about a second. The output is the same as before, byte for byte.

## Underneath

- Built on Prism 0.8.1, the parser seek shares with glint, recap and crux.

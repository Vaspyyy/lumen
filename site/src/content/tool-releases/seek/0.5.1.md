## Faster

- **A search that finds nothing is no longer the slowest one.** When nothing matches, seek looks for names like the one you typed. It did that by recording every name in the project and comparing them all afterwards, which made the search without hits by far the most expensive one, on every core. Agents guess names, so they hit this often. seek now compares each name once and keeps only the ones that are alike. The suggestions are the same.

  In a Rust project of 4,700 files, such a search took 3.3 s, 21 s of CPU time and 620 MB; now 0.4 s, 2.1 s and 80 MB. In a TypeScript project of 31,000 files: 7.1 s, 47 s and 1.2 GB before, 1.1 s, 6 s and 110 MB now.

## New

- **An agent skill.** [`skill/SKILL.md`](https://github.com/Vaspyyy/seek/blob/main/skill/SKILL.md) tells a coding agent when to use seek and how to read what it prints: refs as patterns (`seek file.go:Name`, `seek file.go:104`), the context marks, the `next:` lines and the views. Link or copy it into your agent's skills folder, as with glint, recap and crux.

## Underneath

- **Hits are listed under the definition they are really in** when a type or a value has a `{` or a `;` in it. `fn f() -> [i32; 3] {` ended on its own line before, so the hits in its body were listed under the `impl` around it. That was 1.5% of the functions in a large Rust project. The same went for `func f() interface{} {`, `function f(): { ok: boolean } {` and Kotlin functions with an expression body. Kotlin's `enum class`, `fun interface`, `inner class` and `operator fun` get their names too. This comes with Prism 0.9.0, the parser seek shares with glint, recap and crux.

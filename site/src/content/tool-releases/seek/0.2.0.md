seek now names code the way the other tools of the family do. A ref is a file, a colon and a definition's name (`internal/files/files.go:List`), or a file and a line (`main.go:104`), as compilers print it. Whatever one tool prints can be handed to another as it is.

## New

- **A ref as the pattern shows a definition and its callers.** `seek internal/files/files.go:List` prints the definition of `List` as `-s` would, doc comment included, then the hits of `List` elsewhere in the repository, grouped by the definitions they are in. The path can be just its end (`files.go:List`), and the name the end of a longer one (`files.go:match` for `globSet.match`). A line, `main.go:104`, stands for the innermost definition around it. A name that fits several definitions shows all of them, and one that fits none lists the file's definitions it might mean.
- **A pattern that isn't a ref is searched as before.** One whose path isn't a file is a regular expression as usual, so `seek 'todo:fix'` still searches text, and with `-F` or `-e` the pattern is always a pattern.
- **`seek -d` prints each definition's ref**, with its lines and signature: `internal/files/files.go:List  L73-107  …`.
- **A name defined twice in one file gets a number**: `parse#1`, `parse#2`.

## Changed

- **A range starts at the definition's own line**, as compilers and editors report it: `List` is `L73-107`, not `L70-107` with its doc comment. A hit in the doc comment is still listed under the definition, and `-s` still prints the comment.
- **Paths are relative to the repository root**, also when seek runs in a subfolder, so a ref means the same wherever you are. `-l` keeps printing them from the folder you are in, for the command it is piped to.

See [Refs](https://github.com/Vaspyyy/seek#refs) in the README.

## Underneath

- seek takes its definitions from [Prism](https://github.com/Vaspyyy/prism), the parser it now shares with glint and recap, instead of from glint. The languages are the same.

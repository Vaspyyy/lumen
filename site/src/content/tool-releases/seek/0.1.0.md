The first version of seek: a code search that says where in the code each hit is, not just on which line.

## What is in it

- **Hits grouped by definition.** `seek PATTERN [PATH...]` searches like `rg` or `grep -rn`, but lists every hit under the function, method, class or Markdown section that contains it, with that definition's line range. Names nest the way they do in the code: `Type.method`, `outer.inner`, `worker.onmessage` for a callback set on a property. A hit outside any definition is listed under `(top level)`.
- **A name is a whole word.** A pattern that is a name, or several joined by `|` (`setSpeed`, `load|save`), matches whole words only and minds case, so `seek speed` doesn't find `speedMult` or `Speed`. The line under the header says how many hits that left out, in another case or inside longer words, and gives the command that includes them (`-i --partial`). Other patterns are regular expressions. One that isn't valid, such as `foo(`, is searched as plain text, and the header says so.
- **Hits in comments and strings are labeled** `(comment)` and `(string)`, also in block comments and docstrings that span lines.
- **A view for each question.** `-d` shows only where a name is defined, including fields, module-level constants and a trait's `impl` blocks. `-s` prints the definitions around the hits in full, or the lines around the hits in long ones. `-c` gives one line per definition with its hit count, `-l` only the file names, `-C 3` three lines around each hit, and `--writes` only the hits that set a name: definitions, declarations and assignments.
- **Output within a budget.** seek prints about 100 lines (300 with `-s`; `-b N` sets it, `-b 0` lifts it). When everything doesn't fit, files that define the pattern come first, then source, tests, documentation and data, and lock files, generated and vendored code last. A closing line says how many files got less than asked for.
- **It says what it left out**: hits in another case or inside longer words, files it didn't search, code the budget didn't fit.
- **Suggestions when nothing matches.** seek lists existing names that look like the one you typed, with where they are defined. A qualified name that never appears as text, such as `Repo.Changes` for `func (r *Repo) Changes`, is pointed to its definition.
- **The files git sees.** In a repository, seek searches tracked and untracked files but not ignored ones. Elsewhere it skips caches, build output and dot-folders. `-u` takes them all in, and a path you name is searched even when git ignores it.
- **Plain text when it isn't on a terminal**, and colors when it is (`-A` turns them off). The exit status is grep's: 0 when something matched, 1 when not, 2 on errors.

Definitions come from the outline rules of [glint](https://github.com/Vaspyyy/glint), for Go, Rust, Python, JavaScript and TypeScript, C and C++, Java, Kotlin, C#, GDScript, shell, Lua, Ruby and Markdown headings. In other files the hits are listed without grouping.

## Made for agents

seek was written for AI coding agents. An agent that searches with grep usually reads the code around a hit next, because a line number alone doesn't say which function it is in. seek's output answers that directly.

The README measures it on 1,484 searches agents had made in one JavaScript project. seek's output alone is not smaller than grep's: a small result grows by a line per definition. The saving is in the reads that follow. For the 403 searches that were followed by such reads, grep plus the reads came to 982,920 tokens (the units an AI model reads and pays for). seek's overview alone came to 169,714, 83% less, and `seek -s`, which prints the code itself, to 568,455, 42% less.

Before this release, several models used seek on real projects and tried to break it, over three review rounds. What they found is covered by tests.

## Good to know

- seek matches text, line by line. It doesn't know types or scopes, so a definition made by a macro or by unusual syntax can be missed.
- Look-around and backreferences aren't there: Go's regular expressions don't have them.
- Binary files and files over 32 MB aren't searched.

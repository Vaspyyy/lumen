The first version of peek: a short card about a data file or a log, instead of a screenful of it.

## Made for coding agents

AI coding agents pay for every line they read. In a month of agent transcripts (2026-10-14 to 2026-11-13, about 49,000 shell commands), they read log and output files raw about 4,300 times, and parsed JSON with inline Python 1,552 times, mostly to learn a file's shape and then print one part of it. peek does each of those in one command, with an answer of a known size.

## What is in it

- **JSON: every path once.** Each path in the document gets one line, with its type and what its values look like. Arrays are merged, so `.levels[].id` covers the `id` of every element, and a field that only some elements have says in how many. Strings show their values, or how many different ones there are; numbers show their range. Numbers are shown as written, so 19-digit IDs aren't rounded.

  ```
  $ peek data.json
  peek: data.json  JSON, 374 B, object with 3 keys
  .name                   string                   "aero-run"
  .levels                 array of 3 objects
  .levels[].id            string                   "level_01", "level_02", "level_03"
  .levels[].beats         array of 1 to 3 objects
  .levels[].beats[].t     number                   0.5 to 212
  .levels[].beats[].kind  string                   "tap" ×4, "hold" ×1, "slide" ×1
  .levels[].critic        object                   in 1 of 3
  .levels[].critic.score  number                   7
  .settings               object
  .settings.volume        number                   0.8
  .settings.lang          null
  next: peek data.json '.levels[0]'   the first element in full
  ```

- **A path looks closer.** Every printed path is a jq path and can be given back: `peek data.json '.levels[1]'` prints that part as JSON, with long strings clipped and long lists cut. A path that finds nothing says where it stopped: `no key "levles" in .; its keys: name, levels, settings`.
- **Big objects read as maps.** Where every object at a path has more than 40 keys and their values are all of one kind (IDs that lead to records, say), the card says how many keys there are, with examples, and merges their values under `[]`.
- **JSON Lines, a record at a time**, so a file of any size takes little memory: an 884 MB file of 22,714 records takes a few seconds. The card is the merged shape of all records, and a path is looked up in every record.
- **CSV and TSV**: the columns with their type and values, then the first rows, lined up. Commas, tabs, semicolons and pipes are recognized.
- **Logs, errors first.** The card counts the errors and warnings and lists them in the order they first appear, since the first is often the cause. Lines that differ only in their numbers, hex values and IDs are grouped as one: that is what turns 8,200 progress lines into one line. Then come the first and the last lines. A long line keeps its start and its end and loses the middle, since the end of an error line often says why.
- **An error by its level, then by its words.** A line's level (`error:`, `level=warn`, `[main/WARN]`, `WRN`) decides when it has one. Otherwise words like `error`, `fatal`, `panic` or `failed` and names like `ValueError` do, but not inside a name (`pkg/errors`) or in `0 errors`, and the lines of passing tests (`--- PASS`, `ok  pkg`) don't count.
- **`-g PATTERN`** shows the lines that match a regular expression, grouped the same way. `peek run.log 1200-1240` prints those lines, and `-t N` the last N.
- **Anything else.** A file is read by its extension, else by what is in it, and `--as` says what to read it as. A binary file is named, not printed. Standard input works for every kind: `gh api repos/o/r/pulls | peek`.
- **A budget.** `-b N` sets about how many lines to print, 60 by default. What doesn't fit is counted, not dropped without a word: `… 12 more paths`.

The exit code is 0 when something was shown, 1 when a path, a pattern or a range of lines matched nothing, and 2 for input peek can't read. Three reviews went through it before this tag, and each problem they found has a test of its own.

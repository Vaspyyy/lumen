## Outlines

The outline rules are used by `glint -A <file>`, and by recap and seek. They find more of what is there.

- **Rust.** Definitions are found at any indentation, so the methods of an impl inside `mod tests` or inside a function are listed. Impl blocks with tuples in their generics (`impl<S> World for HashMap<(i32, i32), S>`) or with lifetimes (`impl<'a> Shape for Grid<'a>`) are recognized, and the methods of a generic type are named after the bare type: `Choice.map`, not `Choice<T>.map`.
- **JavaScript.** Functions inside other functions are definitions, and class methods are found when they are indented with tabs, and as getters and setters. In a JavaScript project built of factory modules, these two found about a thousand definitions that were missing before. Functions returned from a factory (`return function update(i) {…}`), functions assigned to properties (`worker.onmessage = (e) => {…}`) and methods in object literals are definitions too.
- **Python.** Functions and classes nested in other functions are definitions: on a Python project of 72 files this added 33 definitions and changed none. Names may have letters outside ASCII (`def über_limit`).
- **A brace or a semicolon in a parameter list no longer ends a definition early.** A destructured JavaScript parameter (`{ a, b = {} }`), a Rust array type (`[f64; 3]`) or a Go struct type among the parameters cut a definition short. This fixed the end of 2,785 definitions in the projects it was checked on.
- **A quote in a JavaScript regular expression (`/"/g`) or a brace in a single-quoted string (`'}'`) no longer throws the brace matching off.** One function then seemed to hold the rest of the file: in a 7,000-line `main.js`, `escapeHtml` swallowed 122 functions.
- **Outlines take less time.** Each rule now looks only at lines that contain one of its keywords (`fn`, `func`, `class`, …). On 3,959 files of real projects the outlines stayed the same, and making them took 39% less time.

## Also new

- **A bare `glint` into a pipe prints the agent map.** `glint` with no flags, whose output goes to a pipe or a file instead of a terminal, now does what `glint -A` does: a program that runs it almost always wants facts, not an `ls`. Any flag keeps the plain listing, and so does `GLINT_PLAIN=1`.

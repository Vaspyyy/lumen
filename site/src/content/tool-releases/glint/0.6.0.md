The outline is glint's list of a file's functions and types, the one `glint -A <file>` prints. This release opens it up to other tools.

## New

- **The outline rules are a public package**, `github.com/Vaspyyy/glint/outline`, and [recap](https://github.com/Vaspyyy/recap) uses it. The rules now know where each symbol ends and which symbol it sits in: by matching braces (skipping strings and comments), by indentation in Python and GDScript, by `end` in Ruby and Lua, and by heading level in Markdown. glint's own outlines look as they did.

## Fixed

- **A `"/*"` inside a string no longer hides the rest of the file.** It was taken for the start of a comment, and every definition after it went missing.
- **Methods are named with their type.** A Go method is `Repo.Open` in the symbol lists of `glint -A --outline`, so two `String` methods on different types can be told apart. Methods in a Rust `impl Trait for Type` block are named after the type.

title: Outline names other tools accept
summary: Each symbol in glint -A <file> has a name that seek, recap and crux accept, and the header's path is relative to the repository. The outline rules moved to Prism, which glint, seek and recap share.

## New

- **Every symbol in an outline has a name you can hand on.** `glint -A <file>` printed only signatures, so a method, a nested function or a Rust impl member had no name you could give another tool. When a signature doesn't show the name as the tools write it, the line now starts with it: `187 globSet.match  func (g globSet) match(p string) bool`, or `5 init#2  func init()` for the second of two `init` functions.
- **The header's path is relative to the repository** you run glint in (absolute for a file outside it). That path, a colon and a symbol's name make a ref: a name for a place in code that [seek](https://github.com/Vaspyyy/seek), [recap](https://github.com/Vaspyyy/recap) and [crux](https://github.com/Vaspyyy/crux) all accept as it is, such as `internal/files/files.go:globSet.match`. The names in `--outline` maps and on the line of C `#define`s are the same. See [Refs](https://github.com/Vaspyyy/glint#refs).

## Fixed

- **A `glint -A` map could lose entries.** While it read a folder, glint added to the same list from two places at once, and entries could be dropped. The automatic checks that now run on every push found it.

## Underneath

- **The outline rules moved to [Prism](https://github.com/Vaspyyy/prism)**, the parser glint, seek and recap now share, so the three find the same symbols. Finding the repository a path is in got about 4.5 times faster with it.
- `github.com/Vaspyyy/glint/outline` still works for Go code that imports it, but it only passes on to Prism and is deprecated.

title: No pipe opened by a read
summary: On Linux, a link that turns into a named pipe while glint reads it no longer gets the pipe opened, and a workspace map no longer loads the symbols of huge source files.
---

## Fixed

- **No named pipe opened by a read.** A named pipe is a special file that one program writes into and another reads from. glint looks at a file before it opens it, so that a pipe is left alone: opening one lets through the program waiting to write to it, which the system then stops (SIGPIPE) when glint closes the pipe again. A link that turned into a pipe between the look and the open still got the pipe opened. On Linux glint now holds on to the path without opening what it names, checks that, and reads only the regular file it looked at. Other systems keep the two steps.
- **No outlines loaded for huge files.** A workspace map loaded the symbols of source files above 4 MiB, which it never outlines. It leaves them out now.

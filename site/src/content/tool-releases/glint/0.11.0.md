This version went with [lumen 0.2.0](/releases/0.2.0/), where a name in a glint listing is the file.

## New

- **`glint --copy FILE...` copies files, not their names.** It puts them on the clipboard the way a file manager's Copy does, so they paste into a file manager, a chat or an upload field. It uses `wl-copy` (from wl-clipboard) on Wayland and `xclip` on X11.
- **A click on a name copies the file**, without opening a file manager first. Turn it on once, then list:

  ```sh
  glint --init copy         # once: makes glint the handler of glint-copy: links
  glint --hyperlink=copy    # names are links that copy the file they name
  ```

  `hyperlink = "copy"` in the config file keeps it on. A desktop notification confirms each click. The terminal has to support OSC 8 links (the standard way for a program to print a link) and hand links it doesn't know to the desktop: Alacritty does, with a plain click and no configuration. lumen copies on a click without starting glint at all; see [Files and links](/docs/files-and-links/).

## Changed

- **`--hyperlink` takes a mode**: `off`, `open` (a click opens the file) or `copy`. A bare `--hyperlink`, and `hyperlink = true` in an existing config file, still mean `open`.

## Good to know

- The link handler copies only files that exist on this machine, and refuses a link that was printed on another one (over SSH).

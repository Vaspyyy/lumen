The first version of glint: an `ls` that shows more where it helps, and a plain-text view of a repository for AI coding agents. It starts in about 4 ms, so it can stand in for `ls`.

## What is in it

- **Listings with icons, colors and git status.** A grid by default, `-l` for a long listing with permissions, sizes, relative times and git status, `-T` for a tree. The icons are characters from a Nerd Font; `--icons never` leaves them out.
- **`glint -p` says what is inside** each entry: the kind of project a folder holds, the line count of a text file, an image's size, the length of a song or a video, how many files an archive holds, a PDF's pages.
- **An interactive browser.** `glint -i` opens a full-screen view with a preview pane: code with syntax colors, Markdown, images, archives and binary files. `f` searches inside the files with ripgrep, and `Enter` opens your editor at the line it found. Rename, move to the trash, copy, cut and paste work in it, `P` jumps to a recent folder or a project, and `M` opens the disk map.
- **A dashboard for a folder of projects.** `glint -P ~/Projects` shows each project's stack, branch, uncommitted changes, last commit and its activity over the last 12 weeks.
- **A disk map.** `glint -M` draws what uses the disk as a treemap, measured the way `du` measures. Build output that can be made again is hatched, and glint says how much you could free and how (`cargo clean`, …). `glint -M -i` lets you walk into it with the arrow keys.
- **A project card.** `glint -C` shows a project's stack, branch, last commit, languages, lines of code and TODOs.
- **Thumbnails** with `--thumbs`: real pictures in terminals that speak the kitty graphics protocol (kitty, WezTerm, Ghostty), colored half blocks elsewhere. `-W` keeps a listing open and updates it as files change, and `--json` prints it for scripts.
- **Git everywhere.** `-c` adds the last commit for each entry, `-H` how often it changes, and `--changed` lists only what has uncommitted changes.
- **Five themes** (`catppuccin`, `tokyonight`, `gruvbox`, `nord`, and `wal`, which follows pywal), a config file at `~/.config/glint/config.toml` (`glint --init config` writes one), and fish integration: completions, and `gi`, which browses and then moves your shell into the folder you quit in.

## For coding agents

- **`glint -A` describes a repository in one call**, in plain text: the stack, the branch, what changed, what git ignores, and then a tree that fits a budget of lines (200 by default, `--budget` to change it). Folders are opened by value: code and docs before media and vendored code.
- **Nothing goes missing without a word.** The top level is always complete, and every cut says what it left out. Numbered files fold into one line (`frame_{001..240}.png ×240`), and in a folder of projects each project gets a one-line glance before any one of them is opened.
- **`glint -A file.go` lists a file's functions and types with their line numbers**, so an agent can read only the part it needs. `--outline` adds each file's symbols to the tree, and `glint -A -M` gives the disk map as text.
- **Fewer tokens.** On a Rust workspace of about 4,000 files, `glint -A` came to about 2,900 tokens, against 13,000 for `tree -L 2` and 50,000 for `git ls-files`, and neither of those says anything about git or line counts.

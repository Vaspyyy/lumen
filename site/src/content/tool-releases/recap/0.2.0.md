recap now names files, functions and lines the way glint, seek and crux do. What one of them prints can be handed to another as it is. The rules for these names, called refs, live in [Prism](https://github.com/Vaspyyy/prism), the library the tools share.

## New

- **`--show` takes a line.** `recap --show group.go:312` shows the changed symbol that holds line 312, so a place that a compiler, a test runner or crux printed can go straight in. If that symbol didn't change, recap says so and lists what did.
- **`--show` takes an older commit.** `recap --show main.go:run@b681ef1` shows what commit `b681ef1` did to `run`, the same as `recap show b681ef1 --show main.go:run`.
- **Two definitions with one name are told apart.** The overview prints `#2` after the second one in a file, and `--show lib.cpp:parse#2` shows just that one.
- **What the overview prints is a ref.** A file's path, a `:` and a symbol's name as shown can be pasted into `--show`, or into glint, seek and crux. A name matches exactly first, then as the end of a longer one (`area` finds `Circle.area`). A name with `::` in it, such as `Foo::bar`, works without a path.
- **Paths are read from the top of the repository first**, the way recap prints them. When the same path read from the current folder would mean another file, recap says so.
- **Colored help**, in the style of glint's.
- **An agent skill.** `skill/SKILL.md` is a file of instructions that teaches a coding agent when and how to use recap. The README says where to copy it.

See [Refs](https://github.com/Vaspyyy/recap/blob/main/README.md#refs).

## Changed

- **The same symbols as seek and glint.** recap and seek were built on different versions of glint's outline rules, so the two could see the same file differently. All three use Prism's rules now: Rust methods are named after their `impl` type, nested functions in Python and JavaScript are symbols of their own, and a Rust signature spread over several lines ends in the right place.

## Fixed

- A changed signature no longer shows a second time among the changed lines below it.
- A file whose changes are all outside its definitions, such as in a Go `var` block, gets its `also lines outside definitions` line. It had none.
- Exported names in Go `internal/` packages are not marked `(public)`.

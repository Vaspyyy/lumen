The first version of pulse: a tool that says what is using the machine, by what, and whether it is too busy for a timing to mean anything. It went public on the day of [lumen 0.5.0](/releases/0.5.0/), which reads it for the light in its title bar.

## What is in it

- **A full-screen monitor.** `pulse` on a terminal opens it. It reads the machine once a second and has four tabs: an overview of the CPU (with a meter for every core), memory, GPU, network and disks, each with a graph of its last minutes; the processes, in groups, one by one or as a tree; T3 Code's agents; and the recorded runs. `/` filters by name, `s` sorts by CPU, memory or GPU, `x` ends a process after asking, and `t` changes the theme. The theme and the tab are remembered.
- **A short card everywhere else.** When its output is no terminal (an agent, a script), `pulse` prints a dozen lines: whether the machine is busy and why, the machine in one line, the heaviest groups of processes, and `next:` lines with the commands worth running after it. `pulse -A` prints the card on a terminal too.

  ```
  $ pulse
  busy: a game (Hades) uses 68% GPU, 2.1 cores and 3.7 GB; cpu at 8.0 of 16 cores, most from t3code agents ×2 (5.6 cores)
  cpu 8.0/16 cores 61°C · mem 24.0/62.0 GB, no pressure · gpu RTX 3070 71% at 168/240 W, 5.8/8.0 GB, 64°C
  top  t3code agents ×2  5.6 cores  4.2 GB
       Hades (game)      2.1 cores  3.7 GB  68% gpu  5.1 GB vram
       firefox ×4        0.4 cores  1.1 GB   3% gpu  300 MB vram
  next: pulse tree 200.yqw   the 3 processes of Hades (game)
  next: pulse agents         the 2 agents, by thread
  next: pulse top --by mem   the biggest memory users
  ```

- **`pulse load`** is one line: `quiet`, or `busy` with the reasons. Busy means a game runs, or the CPU, the GPU or memory are loaded. Run it before you time something: a number measured on a busy machine says little.
- **`pulse top`, `pulse tree` and `pulse agents`**: the heaviest groups of processes (`--by cpu`, `mem` or `gpu`), one process with everything it started and their totals, and T3 Code's agents by thread with their memory limits. A process is named by a handle such as `4821.kfx`, its pid with a dot and three letters, so the name never points to another process later. The pid in front still works with `kill`.
- **What a command costs.** `pulse run -- <command>` runs it and records its CPU time, its peak memory and its stalls (the time it spent waiting for the CPU, memory or the disk). `pulse runs` lists the recorded runs (the last 200 are kept), `pulse show` prints one, and `pulse diff` puts two side by side. A run next to a game or other heavy work is marked as not comparable. Inside a T3 agent, a run gets a cgroup of its own (a group the kernel counts on its own), so its numbers are exact however many processes the command starts.
- **GPU numbers** for NVIDIA cards, through NVIDIA's own library, and for AMD cards. A GPU counts as busy by its power draw against its limit, not by the use it reports: an idle desktop read up to 51% use at 30 of 240 W, because the card had slowed its clock down.
- **A config file**, `~/.config/pulse-monitor/config`, for where busy starts and which other programs count as games. `pulse help config` lists the keys.

The monitor itself takes about 2.2% of one core and 52 MB, reading 630 processes once a second; 27 MB of that is NVIDIA's library.

## In lumen

- **`pulse watch --json`** prints a reading every 3 seconds, one line of JSON each: the load, and what each pid asked about runs and uses. lumen reads it for the light in its title bar, the numbers beside its tabs and what a command cost. See [The machine](/docs/machine/).
- **What pulse names can be clicked.** Handles, run ids and `next:` lines are links in lumen: a click puts the command at the prompt, and doesn't run it.
- **A long `pulse run` says when it is over**, so lumen can mark the tab you looked away from. Ten seconds counts as long; `notify_after` in the config changes that.
- **The monitor wears lumen's colors**, on lumen's own background.

Other terminals see the same output as before. `links = on` in the config turns the links on in another terminal that knows what to do with them.

## Good to know

- pulse is made for Linux, and for a machine where agents run in T3 Code while the same machine is used for games. Elsewhere it shows less, but it works.
- What this version added to the tool as it was: `pulse --version`, and tests that run with every push.

See [pulse](https://github.com/Vaspyyy/pulse).

## New

- **A command that reruns only the failed tests.** When tests fail, the first `next:` line is the command that reruns just those, keeping the original command's flags. Run it to check a fix without the whole suite:

  ```
  next: crux go test -count=1 -run '^TestA$/^bad$|^TestB$' ./a/ ./b/   reruns the 2 failed tests
  ```

- **For `go test`, pytest and cargo**, in the text report and in `--json`, with or without context.
- **Exact names.** Each failed test is passed on as the runner printed it: Go's subtest path, pytest's node ID with its parameters, cargo's test path. So parametrized tests, nested subtests and tests in modules moved with `#[path]` rerun exactly.
- **It says when more runs.** Where the runner's filter can also pick other tests, the reason says so: "also reruns tests of the same name in the other packages", "also reruns passing subtests of TestA".
- **No line rather than a wrong one.** crux leaves it out when it can't be exact: a test ended in an error or timed out, the failures crux read don't add up to the run's own count, a failure's test couldn't be found, more than 20 tests failed, or the runner is one crux can't filter, such as `make test`.

## Fixed

- **pytest's short summary reads test IDs with spaces in them.** With `--tb=no` or `--tb=line`, a parameter with a space in it ended the list, so the failures after it were lost.
- **The note that cargo stops at the first failing target** no longer shows when `--no-fail-fast` was passed.

## Underneath

- Built on Prism 0.8.1, the parser the tools share, which builds the rerun commands.

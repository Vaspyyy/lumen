In a git repository, crux now knows what you are working on without being told: the functions you changed, and the commit recap showed you last. It is the same context seek and recap use, shared through [Prism](https://github.com/Vaspyyy/prism), and crux adds to it.

## New

- **Marks on what you changed.** An `in` or `test` line whose function changed gets a mark: `[changed]` for an uncommitted change, `[branch]` for one committed on this branch, `[focus]` for one in the commit or range recap showed last. A `context:` line at the top says what the marks rest on, such as `context: 1 changed symbol vs HEAD`. An error inside your own change is usually the place to look first.
- **What to run next.** Up to three `next:` lines at the bottom, each a command to run as printed, with its reason: `seek` for the failed test's definition, and `recap --show` for a changed function that the failure is in or that the failing code names.

  ```
  next: recap --show internal/files/files.go:List    the uncommitted change to List, which TestList mentions
  next: seek internal/files/files_test.go:TestList   the failed test's definition
  ```

  "Mentions" means the name is in the text, nothing more: crux has no coverage data, so it never says that a test covers some code.
- **The last run is remembered.** After every run, pass or fail, crux records the command, its exit code, the failed tests and the functions errors are in. The record is kept in the repository's git folder for an hour, one per worktree and agent session. seek and recap read it and mark those functions `[failing]`. A run that never started or was interrupted leaves the record before it in place, so half a run doesn't replace a whole one.
- **`--json` carries it too**, in `context`, `marks` and `test_marks`.
- **`--no-context`** (or `PRISM_NO_CONTEXT=1`) turns it all off and records nothing. The report is then the same, minus the marks, the `context:` line and the `recap` suggestions.

Context loads while the command runs, about as much work as one `git status`, and without taking git's index lock, so it never gets in the way of a git command you run at the same time. Recording the run adds a few milliseconds at most.

## Fixed

- **A file that isn't a regular file can't hang crux.** To name the function an error is in, crux reads the source file. An error placed in a symlink to a device such as `/dev/zero`, or in a named pipe, could make it hang. It now reads only regular files, and a symlink gets no `in` line.

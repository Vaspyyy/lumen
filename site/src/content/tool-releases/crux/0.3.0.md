The first version of crux: put it in front of a build, test or lint command, and read a short report instead of hundreds of lines.

```
$ crux go test -v ./...
FAILED  go test -v ./...  (exit 1, 113ms, 88 lines of output)
tests: 41 passed, 1 failed, 0/1 packages ok

1 failed test:
  TestAdd  calc/calc_test.go:7
    Add(1, 2) = -1, want 3

full log: /home/you/.local/state/crux/logs/20261114-010726.197-2599562-go-test.log
```

## What is in it

- **One short report per run.** `crux cargo test` runs `cargo test`, waits for it and prints the verdict, the test counts, and each error or failed test with its file, its line and the few lines that explain it. Compile progress, passing tests and the standard library's stack frames stay out of the report. The exit code is the command's own.
- **The first line is the verdict**: the command, its exit code (or the signal that ended it), how long it took and how much it printed. A test run gets a `tests:` line with the counts from the tool's own summary. `go test` without `-v` only reports packages, so crux says `3/4 packages ok` then instead of making up a test count.
- **Errors come with what explains them**: the code around the line, or the frames of a stack trace that are in your code. A failed test comes with its assertion or panic message.
- **Repeats are folded.** Three or more errors with the same message become one entry that lists every place. Warnings are folded by kind, with every name: `unused variable [-Wunused-variable] ×2: ‘unused’, ‘y’`.
- **Places work from where you are.** Tools print paths from their own root (a cargo workspace, a folder `make` went into), so crux finds the file and rewrites the path to work from the current folder. A place whose file exists nowhere is marked, which catches stale caches.
- **Notes say when a run did less than it seems**: cargo stopping at the first failing test target, a Go panic ending the rest of its package, a `-run` filter that matched no test, pytest stopping after a collection error, after `-x` or on `Ctrl+C`, a package that didn't build.
- **A budget of about 60 lines**, which `-b` changes. It is soft, and it keeps two promises: the first error or failed test always keeps its explanation, and every error and failed test gets a line (beyond 30 of them, as many as fit). What is cut is announced with a count.
- **Nothing is lost.** The full output goes to a log in `~/.local/state/crux/logs` while the command runs, so it survives a timeout or `Ctrl+C`. Each run gets its own file, readable only by you, kept for a week. `crux --log` prints the path of the latest log from the current folder, so `less "$(crux --log)"` opens it. `--no-log` keeps nothing.
- **English messages.** Commands run with `LC_ALL=C.UTF-8`, so compiler messages look the same on every machine. `--keep-locale` turns that off.
- **At a terminal**, a live status line while the command runs, and the report in color. `-A` asks for the plain report, which is the default when the output doesn't go to a terminal. `-v` also streams the output while it runs, and `-r` prints the whole output, cleaned of escape codes and progress bars, instead of a report.

## The tools it knows

cargo and rustc, `go build`, `go test` and `go vet`, pytest and Python tracebacks, the TypeScript compiler, gcc and clang (also through make and ninja), javac, eslint, Node.js and npm. For anything else, crux shows the output whole if it is short, and otherwise its error-looking lines and its last lines.

## Made for agents

crux was written for AI coding agents, which pay for every line they read, and it works just as well at a terminal. On a set of small broken projects in Rust, Go, Python, TypeScript and C, the raw output of the build and test commands came to about 14,000 tokens (the pieces of text a language model reads) and crux's reports to about 1,500: about 89% less. It saves the most when the output is mostly passing tests or progress (`cargo test` with 400 tests: 96% less) and little when a tool prints little besides its errors (`make` with gcc: 11%).

Before this release, crux went through three review rounds in which several models fixed those projects with it, checked its reports against the raw output and tried to break it; everything they found became a test built from real tool output.

## Good to know

- crux is not for commands whose whole output is the point (`git diff`, `cat`, `--help`), for programs you type into, or for anything that never ends, such as dev servers and watch modes.
- Flags go before the command. Everything after the command's name belongs to the command.
- It is made on Linux and should work on macOS and the BSDs. Windows is not supported.
